# 表情差分の追加手順

プリセットの立ち絵20体はすべて表情差分（10表情の透過画像）を持ち、友達一覧から選べる。
新しい立ち絵を足すとき、または既存の差分を作り直すときは、この手順で10枚を用意して
`PORTRAIT_EXPRESSION_IDS` に ID を登録する。

差分の揃い具合・シーン背景・声・プロフィールは、開発者モード（`#dev`）の
**キャラクター** タブで1画面ずつ確認できる。

---

## 経路は2つ

| | A. Codex（推奨） | B. OpenRouter |
| --- | --- | --- |
| スクリプト | `scripts/generate-portrait-expressions.mjs` | `scripts/generate-portrait-sheet.mjs` |
| モデル | OpenAI GPT Image（Codex 組み込み `image_gen`） | `google/gemini-3-pro-image-preview` |
| 課金 | ChatGPT アカウントのプラン枠 | OpenRouter クレジット（1体 約 $0.245） |
| 出力 | 1表情ずつ 1086×1448 → 合成して 5430×2896 | 5504×3072 のシート1枚 |
| 所要時間 | 1体 約5分（3並列） | 1体 約1分 |
| 前提 | `codex login` 済み（ChatGPT） | `OPENROUTER_API_KEY` |

最初の8体は B で、残りの12体（2026-09-11）は A で作った。画風はどちらも
セル塗りのアニメ調で、並べても違和感はない。OpenRouter の残高を会話・TTS に
温存したいので、以後は A を使う。

---

## A. Codex で作る

### 1. 表情シートを生成する

```bash
node scripts/generate-portrait-expressions.mjs --id pt-nuan
#   → tmp/expr-pt-nuan/sheet.png（5430×2896）
#     tmp/expr-pt-nuan/<expression>.png（個別の生成物）
#     tmp/expr-pt-nuan/reference-sheet.png（参照に使った低解像度シート）
#     tmp/expr-pt-nuan/<expression>.log（Codex の出力ログ）
```

元イラスト `web/public/portraits/<id>.jpg` を Codex に添付し、

1. まず低解像度（1672×941 前後）の 5×2 シートを1枚作らせて「表情の並び・画風・構図」の参照にし、
2. その参照と元イラストを添えて **1表情ずつ** 個別に生成し（既定で3並列）、
3. 10枚を最小サイズに揃えて中央クロップし、5×2 のシートに合成する。

`--parallel 2` で同時実行数を、`--out` で出力先を変えられる。

### 2. 10枚の透過立ち絵へ切り分ける

```bash
node scripts/sheet-to-portraits.mjs --id pt-nuan \
  --sheet tmp/expr-pt-nuan/sheet.png \
  --ref web/public/portraits/pt-shixun-neutral.webp \
  --contact tmp/expr-pt-nuan/contact.png
```

`--ref` は「頭の大きさ・位置を合わせる基準」。完成済みの立ち絵を渡せば、
既存キャラと同じ枠に揃う。`--contact` で出力した確認用シート（透明部分がマゼンタ）を
必ず目視し、髪の周りに背景が残っていないか、10コマで顔が動いていないか、
表情が指示どおりか（neutral が笑っていないか、等）を確認する。

気に入らない表情が1つだけなら、`tmp/expr-<id>/<expression>.png` を差し替えて
`--compose-only true` でシートの合成だけをやり直し、手順 2 を再実行する。

### 3. 登録する

`web/src/data/portraits.ts` の `PORTRAIT_EXPRESSION_IDS` に ID を追加する。
追加を忘れると「表情差分の画像が揃っている立ち絵は、すべて有効になっている」テストが落ちる。

### 4. 確認

```bash
npm run build && npm test
npm run dev:web   # http://localhost:5173/#dev → キャラクター タブ
                  # http://localhost:5173/preview.html?view=expressions
```

## B. OpenRouter で作る

```bash
export OPENROUTER_API_KEY=sk-or-v1-...
node scripts/generate-portrait-sheet.mjs --id pt-nuan --out tmp/sheet-nuan.png
```

以降は A の手順 2〜4 と同じ。

## 落とし穴

### Codex 経路

- **Codex の `image_gen` は出力サイズを指定できない。** 1枚 1000〜1500px 前後しか出ないため、
  シート1枚に10コマ詰めると1コマ 330px になり、拡大でぼやけて使えない。1表情ずつ作るのはそのため。
- **Codex の Windows サンドボックスはファイルを読めない**（`deny-read ACLs`）。参照画像は
  `-i` で添付し、プロンプトで「添付済みの画像を使え・パスで参照するな」と明示している。
  生成物は `~/.codex/generated_images/<session id>/` から拾う。Codex がパスを報告しなかった
  場合はそのセッションのディレクトリ内の最新 PNG にフォールバックし、3回まで投げ直す。
- **`codex` は ChatGPT ログインで動く。** `codex login status` で確認。**Plus プランの枠は
  立ち絵 3〜4 体分（画像 40 枚前後）で尽きる**（2026-09-11 に実測。5時間ほどでリセット）。
  上限に当たるとスクリプトは即座に止まるので、リセット後に同じコマンドを打てば
  生成済みの表情を飛ばして続きから再開する。
- 同時に走らせるキャラクターは2体（＝Codex セッション6本）まで。

### OpenRouter 経路

- **4K が出せるのは `-preview` 系のモデルだけ。** 無印 `google/gemini-3-pro-image` に
  `image_config.image_size: '4K'` を渡すと 400 が返る。
- **応答の `images` は2枚。** 低解像度プレビュー（1376×768）と本命（5504×3072）が入るので、
  必ず**最後の1枚**を使う。
- **OpenRouter のキーには月間上限があり、口座の残高も別にある。** 会話・TTS と同じキーを
  使うため、生成で使い切るとアプリ側が止まる。`GET /api/v1/auth/key`（キー枠）と
  `GET /api/v1/credits`（口座）の両方を確認する。
- **API キーは絶対にコミットしないこと。** スクリプトは環境変数 `OPENROUTER_API_KEY` からのみ読む。

### 共通

- **コマの構図はプロンプトで制御しきれない。** 「もっと引いて腰まで」と強く指示すると
  むしろ寄る。生成結果を受け入れ、`sheet-to-portraits.mjs` の頭サイズ正規化に任せる。
- **wink のピースサインが頭幅の計測に混ざる。** 中心 X が少しずれるが、拡大率は10コマの
  中央値で決まるので大きさは変わらない。既存キャラも同じ。
- 出力の高さは体の短いコマに合わせて決まる（600〜870px の幅で変わる）。ノベル画面は
  `object-fit: cover` で上寄せに表示するので、この差は見た目に影響しない。
