# 声の割り当て機能と管理者ダッシュボード 企画書

- 対象プロジェクト: しゃべチャイナ
- 対象画面: `web/src/components/VoiceSettingsModal.tsx` / 新規「声の管理ダッシュボード」
- 関連ファイル: `web/src/services/ttsCatalog.ts`, `web/src/data/characterVoices.ts`, `web/src/data/presetFriends.ts`, `web/src/services/storage.ts`, `web/src/services/speech.ts`, `web/src/types.ts`
- 文書版: v0.2（T-59 を除き実装済み）
- 作成日: 2026-09-10

---

## 1. 背景

TTSモデル検証モード（T-51〜T-53）での比較テストが一巡し、本番で使う音声の方向性が固まりつつある。

- **最有力候補**: `fish-audio/s2.1-pro-free:free`（S2.1 Pro フリー版）
- **選定理由**: 声の作り込みが細かくできること、話者ID（reference_id）が豊富にあること、コストが無料または非常に安いこと
- **声の出し分け**: 話者IDを友達キャラクター20人へ個別に振り分ける
- **切り替え条件**: フリー版で遅延が実用に耐えないと判断した場合、`fish-audio/s2.1-pro`（有料版）へ移す

まだ確定ではないため、**特定モデルに依存しない形で「モデル＋話者ID＋チューニング値をキャラクターごとに割り当てられる」構造**を作る。

しかし現状、検証結果を本番のキャラクターへ反映しようとしても、声質カスタマイズ画面の「音声モデルを選ぶ」から**モデルを選択できない**。

---

## 2. 目的

1. 声質カスタマイズ画面で音声モデルを選べるようにし、モデルごとに必要な話者ID・パラメータを保存できるようにする
2. 全キャラクターの顔を並べて声設定を俯瞰・変更できる管理者ダッシュボードを用意する
3. 検証モードで得た「良かった組み合わせ」を、そのまま本番キャラクターへ持ち込めるようにする

---

## 3. 現状の問題

### 3-1. モデル一覧が永久に「取得中…」のまま（今回の直接原因）

[VoiceSettingsModal.tsx:188-205](../web/src/components/VoiceSettingsModal.tsx#L188-L205) のカタログ取得 `useEffect` が、**自分自身の状態更新で自分をキャンセルしている**。

```ts
useEffect(() => {
  if (... || catalogState !== 'idle') return
  let cancelled = false
  setCatalogState('loading')      // ← ここで catalogState が変わる
  loadTtsCatalog().then(...)      // ← この then は cancelled=true で捨てられる
  return () => { cancelled = true }
}, [catalogState, hasApiKey, isOpen, provider])   // ← catalogState が依存に入っている
```

`setCatalogState('loading')` → 再レンダリング → 依存配列の `catalogState` が変化 → **前回のクリーンアップが走り `cancelled = true`** → 取得が完了しても `setCatalog()` が呼ばれない。以後 `catalogState` は `'loading'` のままで、先頭のガードにより再取得もされない。

結果、[VoiceSettingsModal.tsx:493](../web/src/components/VoiceSettingsModal.tsx#L493) の `catalog.length === 0` 分岐だけが残り、セレクトは「現在のモデル1件＋空の optgroup 2つ」になる。スクリーンショットの状態と一致する。

同じカタログ取得でも [TtsDebugModal.tsx:104-126](../web/src/components/TtsDebugModal.tsx#L104-L126) は依存が `[isOpen]` のみで、取得中の Promise を `ref` に持つため正常に動く。検証モードでモデルを選べて本番側で選べないのは、この差による。

### 3-2. 取得に失敗したときの逃げ道がない

- APIキー未設定（`hasApiKey === false`）だとカタログ取得自体を行わず、セレクトは現在のモデル1件のみになる
- Worker は取得失敗時に `stale: true` で既知9モデルを返す（[worker/src/routes/tts.ts](../worker/src/routes/tts.ts)）が、`VoiceSettingsModal` は `stale` を読んでおらず、利用者に何が起きたか伝わらない
- `catalogState === 'error'` になったあとの再試行手段がない

### 3-3. 話者IDの持ち方が Kokoro / Qwen 専用になっている

`CharacterVoiceOption` は `kokoroVoice` と `qwenVoice` の2フィールドしか持たない（[characterVoices.ts:6-19](../web/src/data/characterVoices.ts#L6-L19)）。

- `usesCharacterPresets()` は `kokoro` / `qwen` 以外を false にするため、Fish Audio では声質キャラクター一覧そのものが表示されない（[VoiceSettingsModal.tsx:50-52](../web/src/components/VoiceSettingsModal.tsx#L50-L52)）
- Fish Audio の話者ID（reference_id）はチューニングパネルの自由入力欄からしか設定できない
- **声質キャラクターは8種類（男性4・女性4）しかなく、友達は20人いる**。S2.1 Pro の豊富な話者IDで20人を出し分ける今回の方針は、この構造のままでは載せられない

### 3-4. モデルを切り替えると設定が消える

[VoiceSettingsModal.tsx:279](../web/src/components/VoiceSettingsModal.tsx#L279) でモデル変更時に `setTuning({})` を実行する。Kokoro ⇄ Fish を行き来して聴き比べると、戻ってきたときに話者IDもチューニング値も失われている。

### 3-5. 20人分の設定を一覧・比較する場所がない

声設定は「友達カード → 声質ボタン」からしか開けず、1人ずつしか触れない。20人分の割り当て状況（誰がどのモデル・どの話者IDか、重複していないか）を確認する手段がない。

## 6. スコープA｜音声モデルを選べるようにする

### A-1. カタログ取得の修正

`VoiceSettingsModal` の取得処理を `TtsDebugModal` と同じ形へ揃える。

- 依存配列から `catalogState` を外し、`[isOpen, provider]` にする
- 取得中の Promise を `useRef` で保持し、再マウント・再オープンで取り直さない
- 失敗した Promise は ref から捨て、開き直したときに再取得できるようにする

さらに、**取得ロジックを `services/ttsCatalog.ts` のモジュールレベルのキャッシュへ集約**し、声質カスタマイズ画面・管理ダッシュボード・検証モードの3画面で1回の取得を共有する。

```ts
// services/ttsCatalog.ts に追加
export function getTtsCatalogShared(): Promise<TtsCatalog>   // 取得中Promiseを共有・成功時のみ保持
export function invalidateTtsCatalog(): void                 // 「再取得」ボタン用
```

### A-2. APIキーが無くても、失敗しても選べる状態にする

- `hasApiKey` によるカタログ取得の抑止をやめる（`/api/tts/models` はキー無しでも既知一覧を `stale: true` で返す）
- `stale === true` のときはセレクト付近に「一覧を取得できなかったため既知のモデルのみ表示中」と明示し、**再取得ボタン**を出す
- `catalogState === 'error'` でも `FALLBACK_TTS_MODEL_IDS` 相当の選択肢は必ず出す（＝**セレクトが空になる状態を無くす**）
- 空の `optgroup` はレンダリングしない

### A-3. モデル別に設定を覚える（キャラクターごと）

`Voice` にモデル別の記憶領域を足す。現在の `voiceModel` / `voiceTuning` は「いま選択中のモデルの値」として据え置き、後方互換を保つ。

```ts
// types.ts
export interface VoiceModelBinding {
  voiceModel?: string          // そのモデルでの話者ID（Fish なら reference_id）
  voiceTuning?: TtsVoiceTuning // そのモデルでのチューニング値
}

export interface Voice {
  // 既存フィールドは変更しない
  ttsModel?: string
  voiceModel?: string
  voiceTuning?: TtsVoiceTuning
  /** モデルIDごとの話者ID・チューニング値。モデルを行き来しても設定を失わない。 */
  voiceByModel?: Record<string, VoiceModelBinding>
}
```

- モデル切替時: 現在値を `voiceByModel[旧モデルID]` へ退避 → `voiceByModel[新モデルID]` があれば復元、無ければ既定値を解決
- 保存時: `voiceByModel` ごと `saveFriendVoice()` で永続化（[storage.ts:298](../web/src/services/storage.ts#L298)）
- 再生時: [speech.ts:204-224](../web/src/services/speech.ts#L204-L224) は既に `voice.ttsModel` / `voice.voiceModel` / `voice.voiceTuning` を尊重するため、**Worker 側の変更は不要**

### A-4. 話者IDの持ち方をモデル横断にする

`CharacterVoiceOption` にモデル別の話者IDテーブルを足す。既存の2フィールドは互換のため残す。

```ts
export interface CharacterVoiceOption {
  // ...既存
  edgeVoiceName: string
  qwenVoice: string
  kokoroVoice: string
  /** モデルID接頭辞 → 話者ID。例: { 'fish-audio/': '<reference_id>' } */
  voiceIdsByModel?: Record<string, string>
}

/** 選択中モデルでの話者IDを解決する。未登録なら undefined を返し、UI側で入力を促す。 */
export function resolveVoiceIdForModel(option: CharacterVoiceOption, modelId: string): string | undefined
```

`usesCharacterPresets()` の判定を「モデルIDに kokoro / qwen を含むか」から「**そのモデルの話者IDを解決できる声質キャラクターが1件以上あるか**」へ変える。これにより Fish Audio でも声質キャラクター一覧から選べるようになり、未登録モデルでは従来どおり話者一覧・自由入力にフォールバックする。

### A-5. 20人分の既定話者IDを用意する

`presetFriends.ts` の `voice()` ヘルパーを拡張し、20人それぞれに S2.1 Pro 向けの reference_id を既定値として持たせる。

- 話者IDの選定は Fish Audio のボイス一覧（<https://fish.audio/discovery/>）から、性別・年齢感・キャラクター性に合わせて人手で選ぶ
- **選定作業自体は実装タスクとは別**（後述 T-59）。実装時点では「未割り当て」を許容し、未割り当てのキャラクターは管理画面で目立たせる
- 既定値が無いキャラクターは、従来どおりモデル既定の声にフォールバックする（会話は止めない）

## 7. スコープB｜声の管理ダッシュボード

### B-1. 入口

- URL: `https://<app>/#admin`（`index.html` 内。本番バンドルに含まれる）
- 設定モーダルの下部に「声の管理ダッシュボードを開く」導線を置く
- 認証は設けない。個人利用前提のため、URLハッシュによる導線分離のみとする（要件定義書の「個人利用前提」に準拠）
- ダッシュボードを閉じるとハッシュを外して通常画面へ戻る

### B-2. 画面構成

```
┌──────────────────────────────────────────────────────────┐
│ 声の管理ダッシュボード                            [× 閉じる] │
├──────────────────────────────────────────────────────────┤
│ 一括操作: モデル [fish-audio/s2.1-pro-free ▾] [全員に適用]   │
│ 表示: [すべて 20][女性 10][男性 10][未割り当て 3] [通し試聴 ▶]│
├──────────────────────────────────────────────────────────┤
│ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐              │
│ │  顔    │ │  顔    │ │  顔    │ │  顔    │              │
│ │ 陈美玲 │ │ 李雪   │ │ 林子涵 │ │ 苏雨辰 │              │
│ │S2.1free│ │S2.1free│ │S2.1free│ │ kokoro │              │
│ │ spk-a  │ │ spk-b  │ │⚠ 未設定│ │ zf_... │              │
│ │ ▶試聴 ⚙│ │ ▶試聴 ⚙│ │ ▶試聴 ⚙│ │ ▶試聴 ⚙│              │
│ └────────┘ └────────┘ └────────┘ └────────┘              │
│ … 20人分 …                                                │
└──────────────────────────────────────────────────────────┘
```

カード1枚の表示項目:

- 顔アイコン（`FriendAvatar` を再利用）と氏名
- 現在のモデル名（短縮表示）／話者ID／チューニング要約（`describeTuning()` を再利用）
- 話者ID未設定の警告バッジ、**他キャラと話者IDが重複しているときの重複バッジ**
- ▶ 試聴（そのキャラの声で1文を再生。再生中は停止ボタンへ）
- ⚙ 個別設定 → 既存の `VoiceSettingsModal` をそのまま開く（設定UIを二重に持たない）

### B-3. 機能①｜全員まとめてモデル切替

- 上部のモデルセレクトで選び「全員に適用」を押すと、20人の `ttsModel` を一括変更する
- **話者IDとチューニングは各自の `voiceByModel` から復元**する（A-3 の仕組みをそのまま使う）
- 適用前に、対象人数と話者ID未解決になる人数を確認ダイアログで示す
- 直前の状態を1段階だけ保持し「元に戻す」を出す

### B-4. 機能②｜一覧からその場で試聴

- カード単位の試聴に加え、上部の「通し試聴」で表示中のキャラクターを順に1文ずつ再生する
- 再生中のカードを強調し、任意の時点で停止できる
- 試聴文は共通の1文（例: `你好！我是○○。很高兴和你用中文聊天！`）とし、名前だけ差し替える
- **API利用料が発生するため**、通し試聴の実行前に対象人数を明示して確認する（検証モードと同じ扱い）

### B-5. 機能③｜検証モードの結果から取り込み

- `ttsDebugStorage` に保存済みの検証履歴（`TtsDebugRun`）を読み、「モデル＋話者ID＋チューニング値」の組み合わせ一覧として提示する
- 一覧から1件選び、割り当て先のキャラクターを選ぶと、そのキャラの `Voice` へ反映する
- 評価（`ratings`）とメモ（`memo`）を添えて表示し、どれが良かったか思い出せるようにする
- 取り込みは1件ずつ。誤爆を避けるため一括割り当ては設けない

## 9. 受け入れ条件

1. 声質カスタマイズ画面の「音声モデルを選ぶ」で、OpenRouter が返す音声出力モデルを選択でき、選んだモデルの説明・価格が表示される
2. モデル選択後に話者IDとチューニング値を設定し、保存 → 再度開いたときに同じ値が復元される
3. Fish Audio S2.1 Pro フリー版を選び、話者IDを指定した状態で会話すると、その声で読み上げられる
4. モデルを切り替えて戻したとき、以前のモデルで設定した話者ID・チューニング値が失われていない
5. APIキー未設定でも、モデル一覧が既知のモデルにフォールバックして表示され、状態が説明される
6. `#admin` で管理ダッシュボードが開き、20人の顔・モデル・話者IDが一覧できる
7. 一括モデル切替を実行すると全員のモデルが変わり、各自の話者IDは保持される
8. `npm run build` と `npm test` が通過する

## 10. リスクと保留事項

| 項目 | 内容 | 対応 |
| --- | --- | --- |
| フリー版の遅延 | `s2.1-pro-free:free` は混雑状況で遅延が変わる（`openRouterTtsModels.ts` に記載済み） | 実会話での遅延を計測し、実用外なら `s2.1-pro` へ。`voiceByModel` により切替コストは低い |
| 話者IDの永続性 | Fish Audio 側で reference_id が削除・変更される可能性 | 再生失敗時はモデル既定の声へフォールバックし、会話を止めない。管理画面で失敗を可視化 |
| 20人分の選定コスト | 話者IDの人手選定に時間がかかる | 未割り当てを許容する設計にし、埋まった分から順に反映 |
| 課金 | 通し試聴20人＝20リクエスト。UTF-8バイト課金のため中国語は割高 | 実行前確認を必須にし、試聴文は1文に固定 |
| 管理画面の露出 | `#admin` は誰でも開ける | 個人利用前提のため許容。破壊的操作（一括適用）に確認と「元に戻す」を付ける |
